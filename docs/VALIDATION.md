# Validation

0.3.2의 사전 검증 범위입니다. 제공된 자료로 수정한 뒤 재실행한 개발 회귀 검사이며 독립 최종 시험이 아닙니다.

| 항목 | 결과 |
| --- | --- |
| 캡처 | 46장, 서로 다른 이미지 45장 |
| 아이템 관측 | 45장에서 641건, 반복 화면 포함 |
| 툴팁 화면 | 8장, 중복 포함 |
| 회귀 검사 | 45장: 격자·아이템 식별/영역·수량·선택·툴팁 옵션/비용/연결·확인창 억제. 별도 1장: 창 검출·격자 위치·보류 모드 |
| 회귀 오류 | 0건 |
| C# 단위 검사 | 112개 통과 |
| Python 평가 도구 검사 | 4개 통과 |
| 독립 폴더 EXE 실행 | 자료 자동 전개 및 PNG 렌더 확인 |

원본 캡처와 정답은 공개 저장소에 포함하지 않습니다. 비공개 자료를 가진 개발자는 `tools/replay_regression.py`로 전체 재현 검사를 실행할 수 있습니다. 새로운 파일이나 해시 변경이 있으면 검사가 실패합니다.

네트워크 제한·캐시·유사 옵션 검색은 모의 HTTP 응답으로 시험합니다. 실제 서비스에 부하를 가하는 시험은 하지 않습니다. 요청을 줄인 것이 실제 서비스의 특정 응답 시간을 보장하지는 않습니다.

미완료: 독립 1,000장/10,000개 아이템 시험, 모든 카탈로그 항목, HDR, 전체 해상도/창 모드 조합, 모든 보류/흑백 상태, 게임 프레임타임 영향, 전체 첫 가격 표시 p95 500ms, 툴팁 p95 300ms.

## 0.2.0 가격 캐시 검증

- 실제 poe.ninja 23개 분류 수집 성공. 개발 캡처의 112개 아이템 ID에 가격 연결. 동일 이름의 변형은 표본 최다 대표값과 추정 표시를 사용합니다.
- Sacred Bloom의 Ritual 분류 응답과 기본 통화/환율 변환 확인.
- 모의 서버로 분류별 1회 요청, 동시 초기화 합치기, 조회 시 네트워크 0회, 재실행/리그 분리, 30분 만료, 304 및 비표준 약한 ETag, 429 재시도 기한 보존, 갱신 실패 시 오래된 값 유지, 3시간 초과 폐기를 검사했습니다.
- 화면 닫힘의 헤더 검출은 합성 자료로 검사했습니다. 실제 게임에서 캡처 세션 종료 후 Windows 노란 선이 사라지는지의 실전 검증을 대신하지 않습니다.

## 0.2.1 보류 메뉴와 창 닫힘

- 추가 실물 캡처 30장: 열림 29장, 닫힘 1장, 보류 화면 18장. 초기 창 검출·기존 위치의 창 유지 판정·보류 모드 판독 오류 0건. 이 30장에 대한 전체 아이템 정답 검증은 포함하지 않습니다.
- 제목과 공물 표시가 가려진 상태에서 보류 버튼과 격자 무늬를 확인하는 합성 검사를 0.75/1/1.5/2배 크기로 실행했습니다. 굵은 노란 아이템 테두리를 포함합니다. 버튼만 있거나 격자만 있는 화면은 거부합니다.
- 공물 아이콘의 수평 이동, 한 프레임 실패 후 복귀, 연속 두 프레임 실패를 검사했습니다.
- 기존 버전은 실패 프레임을 저장하지 않아 사용자가 보고한 선택 순간의 원본이 없습니다. 실제 선택 동작의 완전한 재현은 미검증입니다. 0.2.1부터 감지 실패/종료 직전 화면도 자동 저장합니다.

창 상태만 재생하려면 `Ritual.Cli window-state <캡처 폴더> --data data --out work/window-state.json`을 사용합니다. 출력은 판독 결과이며 자동 생성된 정답이 아닙니다.

## 0.2.2 오래된 가격 표시

- 30분이 지난 환율과 3시간이 지난 가격을 계속 사용하고 `*`로 표시합니다. 7일 전 시세가 DB 정리와 앱 재실행 후에도 남는지 검사했습니다. 이전의 3시간 폐기 기준은 제거했습니다.
- 가격과 함께 저장한 환율로 묶음을 환산합니다. 1 div 미만/경계/이상, 수량으로 경계를 넘는 경우, 오래된 환율만 사용한 경우, 환율을 한 번도 받지 못한 경우를 검사했습니다.
- 환율 없는 갱신 응답은 기존 환율을 보존합니다. 해당 응답을 304로 재확인해도 보존한 환율의 확인 시각을 새 시각으로 바꾸지 않습니다.
- 아주 작은 양수 가격을 `0`으로 반올림하지 않고 `<0.01`로 표시합니다.
- 영상 인식은 0.2.1과 같습니다. 기존 캡처 회귀 결과는 0.2.1 실행 결과이며, 0.2.2에서는 오래된 캐시를 이용한 화면 재생과 가격 표시를 확인합니다.


## 0.2.3 가격 색상

- 같은 의식의 일반 화면과 공물 부족으로 흑백이 된 실제 화면 2장을 동일한 캐시로 재생했습니다. 각 화면에 가격 라벨 16개를 표시합니다.
- 기존 버전에서 색이 달라지던 신성한 꽃·징조 라벨의 글자 픽셀을 비교했습니다. 수정 후 두 화면의 색이 각각 일치합니다. `~` 표시는 인식 신뢰도에 따라 유지됩니다.
- 가격 색상 계산에서 인식 추정 조건을 제거했습니다. 추정 시세도 묶음 가격으로 색을 정하며, `≈`와 오래된 값의 `*`는 계속 표시합니다. 가격·수량·환율 미확인은 중립색을 사용합니다.
- 시세 추정/오래됨의 네 조합과 가격/환율 부재를 단위 검사했습니다. 로컬 단일 EXE를 별도 폴더에서 실행해 두 화면을 렌더했습니다.
- 영상 인식 변경은 없습니다. 당시 38장/526건 전체 회귀 수치는 0.2.1 실행 결과이며 이번에는 색상 문제를 재현한 두 화면을 확인했습니다.


## 0.2.4 보류 실패 안내

- 상단 제목·공물·보류 버튼을 가리는 실제 보류 실패 화면을 재생했습니다. 새 창 검출과 보류 모드 판정이 통과합니다. 이 화면은 창 상태와 격자 위치만 정답을 검토했으며, 아이템별 정답을 검증한 526건에 포함하지 않습니다.
- 하단 ‘아이템 보류’ 문구와 2개 이상의 행에 있는 빈 격자 무늬 6개를 함께 확인합니다. 문구만 있거나 격자만 있는 합성 화면은 열린 의식 창으로 인정하지 않습니다.
- 0.75/1/1.5/2배 합성 화면에서 상단이 모두 가려져도 연속 프레임이 캡처 종료를 유발하지 않는지 검사했습니다. 실제 창 부재는 연속 두 번 확인하면 종료합니다.
- 기존 창 상태 캡처 30장(열림 29장·닫힘 1장, 보류 화면 18장)을 다시 검사했고 오류가 없습니다.
- 전체 회귀 검사를 이번 버전에서 다시 실행했습니다. 39장, 아이템 관측 526건, 툴팁 화면 7장에서 정의한 검사 오류 0건입니다. 영상 분석만의 p95는 약 425ms이며 캡처·OCR·시세 조회·첫 표시 시간은 제외합니다.
- 실패 메시지 뒤 실제 게임에서 반복 입력하는 동작은 아직 실전 검증하지 않았습니다. 원본 재생과 상태 전이 검사를 사용했습니다.


## 0.3.0 키보드/마우스 및 다른 폰트

- 한 사용자의 2560×1440 실제 화면 7장입니다. 두 의식 구성에서 아이템 관측 115건(서로 다른 카탈로그 항목 15개)을 원본과 참조 그림으로 대조했습니다. 전부 수량 1이며, 일반 화면·보류 모드·흑백·마우스 호버 상태를 포함합니다.
- 기존 버전은 오른쪽 소지품의 더 선명한 격자 무늬를 선택해 7장 모두 의식 창을 놓쳤습니다. 여러 격자 후보를 검토하고 의식 표식이 있는 후보를 선택합니다. 별도 창끼리 간격과 정렬이 같은 경우도 합성 검사했습니다.
- 툴팁에 가려져 떨어져 보이는 격자 부분은 먼저 함께 검토합니다. 기존 컨트롤러 캡처에서 잘못된 격자 원점 이동이 생기지 않는지 다시 검사했습니다.
- 다른 폰트의 수량 1에 대해 두 개의 작은 숫자 마스크를 추가했습니다. 새로운 115건의 수량 미확인은 0건입니다. 다른 폰트에서 수량 2 이상인 실제 사례는 제공되지 않았습니다.
- 마우스의 초록 호버 테두리를 판독하고 아이템 위쪽에 뜬 작은 툴팁을 검출합니다. 신성한 꽃 툴팁 1건의 이름, 공물 861점, 0:0 위치 연결을 확인했습니다. 이 폰트에서 8을 B로 읽더라도 앞자리를 버려 61점으로 처리하지 않습니다. 숫자 필드에 해석할 수 없는 문자가 있으면 비용 미확인으로 남깁니다.
- 전체 46장/641건/툴팁 8장 회귀 검사의 정의된 오류 0건, 별도 창 상태 30장 오류 0건입니다. 영상 분석만의 p95는 이 개발 PC에서 약 429ms이며 OCR·캡처·가격 표시까지의 시간은 제외합니다.
- 마우스의 고유 아이템 툴팁·아래쪽이나 옆쪽 툴팁, 다른 폰트·해상도 조합, 친구 PC의 실제 게임 성능은 이 자료로 검증하지 못했습니다. 캡처 메타데이터의 기존 controller-ko 표시는 입력 모드의 정답으로 사용하지 않았습니다.

## 0.3.1 초버 차버 툴팁

- 추가로 제공된 컨트롤러 화면에서 선택된 초버 차버의 그림은 맞게 인식했지만 OCR 이름이 ‘초버 자비’여서 툴팁 결과가 없었습니다. 수정 후 선택 위치 2:4, 이름, 옵션 6개, 구매 공물 1,215점, 비타락 상태를 원본과 대조했습니다. 이 추가 화면은 해당 아이템과 툴팁만 검증했으며 전체 641건 집계에는 포함하지 않습니다.
- 한글 자모의 차이가 두 개 이내인 명확한 이름 후보를 사용합니다. 선택된 그림의 신뢰도 0.90 이상, 크기 일치, 사전에 맞는 옵션 세 개 이상이 동시에 필요합니다. 선택 부재·낮은 신뢰도·잘못된 크기나 그림·경쟁 이름·옵션 부족·다른 정확한 이름을 검사했습니다.
- [PoE2DB 초버 차버](https://poe2db.tw/us/Chober_Chaber)의 옵션 표는 +1이지만, 같은 페이지의 버전 기록은 +2–3이고 거래 예제는 +2입니다. 제공된 실물 툴팁도 +2입니다. 이 불일치를 `data/catalog-mod-corrections.json`에 출처와 함께 기록하고 정정했습니다. 갱신 시 원본 구조가 예상을 벗어나면 검토를 요구합니다.
- 모의 HTTP 응답에서 영문 고유 이름과 온라인 조건으로 검색하고, 매물 10개 중 +2 매물 5개만 옵션 시세에 사용하는지 확인했습니다. +1 및 범위 밖 값은 판독 불완전으로 유지합니다. 실제 거래소에 대한 새 조회 시험은 실행하지 않았습니다.
- 기존 캡처 46장·641건·툴팁 8장 회귀 검사 오류 0건입니다. C# 106개·Python 4개 검사를 통과했습니다.

## 0.3.2 의식 징조 수량

- 사용자가 제공한 의식 규칙에 따라 징조 수량을 1로 적용합니다. 인벤토리 최대 중첩 수량은 바꾸지 않습니다. 수량이 달라지는 다른 커런시의 OCR과 수량 미확인 처리는 유지합니다.
- 최신 컨트롤러 캡처 세션에서 PNG와 메타데이터 해시가 일치하는 52장을 복사해 전후 비교했습니다. 의식 격자 검출 48장, 창 부재 4장이며 아이템 관측은 1,598건입니다. 징조로 식별된 관측 1,034건은 모두 수량 1입니다.
- 기존 수량 미확인 82건(물물교환 46, 혼란스러운 효율 18, 상위 찬미 9, 고대인 9)이 수정 후 0건입니다. 반복 화면을 포함한 수량 동작 비교이며, 이 새 세션의 아이템 식별 정답을 독립 검증했다는 뜻은 아닙니다. 수량 외 아이템 결과와 다른 커런시의 수량은 이전 결과와 같습니다.
- 수량 미확인 징조 8개가 있던 보류 화면을 전후 EXE에서 같은 오프라인 시세 캐시로 재생했습니다. 수정 후 8개 모두 가격 라벨을 표시합니다.
- 숫자가 없는 이미지에서도 알려진 단일 수량 항목만 있으면 OCR에 접근하지 않는지 검사했습니다. 잘못된 이전 수량, 흑백·보류·추정 상태, 인벤토리 중첩 상한 보존, 다른 커런시로 이름을 수정할 때 기존의 1개 가정을 버리는 경우도 검사했습니다.
- 기존 46장·641건·툴팁 8장 회귀 검사 오류 0건, C# 112개·Python 4개 검사 통과입니다.
